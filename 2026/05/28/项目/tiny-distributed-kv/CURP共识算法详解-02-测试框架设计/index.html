CURP共识算法详解-02-测试框架设计

Vanilla-Beauty
2026-05-28
项目 › tiny-distributed-kv
C++, 分布式系统, 测试框架

本节介绍 CURP 实现的测试框架设计，用于验证正确性、活性和性能。

1 框架目标

验证 CURP 实现的正确性，包括：

  • 安全性（Safety）：线性一致性、数据不丢失
  • 活性（Liveness）：系统持续运行
  • 性能（Performance）：快速路径成功率

2 核心组件

3 Network Simulator

3.1 功能

  • 延迟模拟：消息延迟指定时间
  • 丢包模拟：按概率丢弃消息
  • 网络分区：模拟节点间通信中断
  • 消息重排序：打乱消息顺序

3.2 接口

4 Node Controller

4.1 功能

  • 启动/停止节点
  • 模拟崩溃：立即停止，丢失内存状态
  • 恢复节点：从持久化状态恢复
  • 控制时钟：加速/暂停时间

4.2 接口

5 Consistency Checker

5.1 功能

  • 线性一致性验证：使用并发算法验证
  • 数据完整性检查：验证所有写入都被持久化
  • CURP 特性检查：验证快速路径正确性

5.2 方法

  • 记录所有操作和响应时间戳
  • 构建实时序关系图
  • 检测是否存在循环依赖

6 测试场景

6.1 基本正确性

  • 单节点写读
  • 多节点并发写
  • 快速路径验证

6.2 故障恢复

  • Master 崩溃恢复
  • Witness 崩溃恢复
  • 同时崩溃恢复

6.3 网络故障

  • 网络延迟
  • 网络分区
  • 消息丢失

6.4 极端情况

  • 高并发
  • 大量故障
  • 恢复过程中新故障

7 测试指标

指标 说明 目标值
快速路径成功率 1 RTT 完成的比例 > 90%
写延迟 平均写操作延迟 < 10ms
恢复时间 崩溃后恢复时间 < 1s
数据丢失率 故障后数据丢失比例 0%
线性一致性违反 检测到的不一致次数 0

9 集成测试示例

10 总结

测试框架是 CURP 实现的关键组成部分，通过：

  • Network Simulator 模拟各种网络条件
  • Node Controller 控制节点生命周期
  • Consistency Checker 验证系统正确性

确保 CURP 实现满足安全性、活性和性能要求。
